## 一、学习目标回顾

1. 理解「为什么 Coding 是开放任务型通用 Agent 的核心」：代码生成是**元能力**——运行时动态创造新工具/约束/表达形态，不必预做所有工具
2. 掌握 Coding Agent 的七个核心工具与整体流程，明确完成标准是**测试通过**而非「代码写完」
3. 理解 Harness 工程四原则：约束优先于指导、验证自动化、快速结构化反馈、可靠回退
4. 在 Windows + SiliconFlow 环境下真实跑通一次「写文件 → 执行 → 看输出 → 收尾」的自主闭环
5. 体验「元能力」方向中的生成式 UI：一次提交的动态澄清表单
6. 理解交互空间在「时序」维度的扩展：异步工具并行、运行中打断/取消、状态检查点跨会话恢复

## 二、核心知识脉络

本章回答：**Coding Agent 本体怎么搭，以及「写代码」为什么是一种元能力。**

- **七个核心工具**：Code Interpreter、Bash、读/写/编辑文件、Glob、Grep（正文指出一个 Bash 其实也够用，Codex 即如此）
- **整体流程**：项目文档化（CLAUDE.md/AGENTS.md 指令文件）→ 需求澄清 → 设计文档 → 代码实现 → **测试-修复循环** → 自审 → 文档同步
- **Harness 工程**：Coding 是可验证性最高的任务——测试套件 + Linter + Git 天然构成 Harness。工具报错不是终点，而是喂回模型的结构化输入
- **故障恢复四级**：API 层 / 工具层 / 上下文层 / 控制流层；检测靠错误分类 + 重复指纹 + 空闲看门狗；恢复分级为静默重试 → 降级接续 → 暴露用户；每条恢复路径设熔断上限防「死亡螺旋」
- **元能力六方向**（由内向外）：思考工具、业务规则约束、多媒体生成、系统适配器、生成式 UI、Agent 自举。本章多个实验的正式结论是**负结果**（5-3、5-4、5-5、5-16 均未显著占优），负结果同样作为一等公民保留。

**Chapter 6 补入的主线**：本章从「模态」与「时序」两个维度扩展 Agent 的观察/动作空间。模态方向（语音、Computer Use、机器人）依赖麦克风、付费语音 API、Docker/VL 大模型或机器人硬件，本机不具备；时序方向的核心是 **6-2 异步框架**——事件队列按紧急度分派（打断 / 立即处理 / 排队）、异步工具并行、安全点取消、检查点持久化。三个共享原语：唤醒、安全点、取消。

| 结果 | 数量 | 说明 |
| --- | --- | --- |
| Passed | 162 | 工具执行、消息渲染、会话状态、上下文管理全部通过 |
| Failed | 3 | 均为**测试用例硬编码 bash 方言**导致的平台差异，非被测代码缺陷 |

3 个失败的具体原因：

1. `test_command_with_exit_code`：用 bash 内建命令 `false` 造退出码 1，PowerShell 无此命令
2. `test_persistent_shell_session`：用 `export PERSISTED_VAR=hello` 验证环境变量持久化，PowerShell 的等价写法是 `$env:`
3. `test_background_job_inherits_persistent_environment`：同样依赖 `export`，且 PowerShell 非交互模式混入 CLIXML 进度流

被测的 [shell_session.py](file:///d:/ai-agent-book/task4/coding-agent/tools/shell_session.py) 本身已做了跨平台适配（按 `os.name` 选 cmd / PowerShell，含换行 CR 处理、`$LASTEXITCODE` 捕获），所以这 3 项判定为**测试脚本的平台方言问题**，如实记录，不通过改测试去「刷绿」。

### B. 真实闭环：SiliconFlow Qwen3-8B 自主完成编码任务

**任务 prompt：**

> 创建 hello_world.py：打印 Hello, World!，包含按姓名问候的函数 greet(name) 和 main 演示块，然后运行 python hello_world.py 验证输出。

**第一次运行——踩到一个真实的「死亡螺旋」：** 模型写完文件后连续 13 次重复执行 `python hello_world.py`，直到触达迭代上限。排查发现：

- 命令退出码 **9009**（Windows 上「命令未找到」）
- 根因：`subprocess` 以 `-NonInteractive` 启动 PowerShell 时，PATH 中的 `python` 解析到 `C:\Users\XGY\AppData\Local\Microsoft\WindowsApps\python.exe` —— 这是微软商店的**占位别名程序**，非交互环境直接失败，输出为空
- 模型看不到任何输出，又被要求「运行验证」，于是反复重试同一个动作——正好复现了正文讲的控制流层故障

**三处 Windows 跨平台适配修复：**

| # | 文件 | 问题 | 修复 |
| --- | --- | --- | --- |
| 1 | [write/edit/multi_edit_tool.py](file:///d:/ai-agent-book/task4/coding-agent/tools/write_tool.py) | 写后 lint 硬编码 `python3 -m py_compile`，Windows 无此命令（3 个测试因此失败） | 改用 `sys.executable` |
| 2 | [main.py](file:///d:/ai-agent-book/task4/coding-agent/main.py) | `Config.validate()` 强制 openai provider 的模型名以 `gpt-`/`o1-` 开头，第三方兼容端点的 `Qwen/Qwen3-8B` 被拒 | 显式传 `--base-url` 时跳过厂商前缀校验 |
| 3 | [system_state.py](file:///d:/ai-agent-book/task4/coding-agent/system_state.py) / [shell_session.py](file:///d:/ai-agent-book/task4/coding-agent/tools/shell_session.py) | 工作目录环境变量未被读取；WindowsApps 占位 python 退出 9009 | 支持 `WORKING_DIRECTORY` 环境变量；把当前解释器目录前置到子进程 PATH |

第 3 项是 Harness 思路的体现：**不是反复在 prompt 里叮嘱模型「用绝对路径」（实测 8B 小模型并不听话），而是让环境本身保证 `python` 可用**。

**第二次运行——闭环成功：**

```text
✅ Task completed!
   Iterations: 4
   Tool calls: 3
```

轨迹：

1. Iter 1：`Write` → 写入 [hello_world.py](file:///d:/ai-agent-book/task4/workspace/hello_world.py)，即时 lint 无错误
2. Iter 2：`Bash` → `python hello_world.py`，看到输出 `Hello, World!`（期间还有一次 Read/Grep 自查）
3. Iter 4：输出收尾总结，自主结束

生成的文件：

```python
def greet(name):
    print(f"Hello, {name}!")

if __name__ == "__main__":
    greet("World")
```

费用：仅 4 轮短上下文对话，代金券消耗极小。

### D. Chapter 6 异步核心：6-2 Flux 事件驱动框架（离线零费用）

对应正文「交互：观察与动作空间的扩展」的时序方向。同步 ReAct 里 Agent 调一个工具就得干等；Flux 把长任务做成**异步**：调用立即返回 `task_id` 占位符，真实子进程在后台跑，完成后作为新事件（`async.result`）注入收件箱。

**三个离线能力（真实测量，`python demo.py`）：**

| 能力 | 实测结果 | 说明 |
| --- | --- | --- |
| ① 并行 vs 串行 | 串行 **4.55s** → 并行 **1.50s**，加速 **3.03x** | 四个独立只读工具 `asyncio.gather`，墙钟由「求和」降到「取最大」 |
| ② 打断/取消/恢复 | 三任务进度冻结在 36%/24%/12%，随即新任务 T4 正常完成 | 「取消」在安全点 terminate 真实 PID；即时提问（现在几点）不打断后台 |
| ③ 检查点持久化 | 3 条轨迹 + 任务 21%/7% 跨会话完全还原 | 运行中任务恢复为 `suspended`，由上层决定重跑还是续跑 |

**紧急度三类分派（简单可解释）：** 取消/停止 → 立即取消当前轮与后台任务；提问（带问号）→ 立即回答但不动后台；其他补充指令 → 进 pending 队列，等异步结果到达时批量追加、只触发一次 LLM。

**Canonical 验收（`python run_real_experiment.py`，19.2s）：** 书中四个场景（异步+即时提问 / 排队批量出日语 HTML / 打断恢复 / 并行+50% 阈值取消）全部以**真实白名单子进程**（`shell=False`，无模拟终端结果可蒙混）留证，**9 项门禁全 passed**，见 [summary.json](file:///d:/ai-agent-book/task4/async-agent/validation/experiment_6_2/20260927T073835Z/summary.json)。

**Ch.6 其余实验按门槛跳过：** 6-4~6-7 语音（麦克风/Whisper 大模型/Fish Audio 付费）、6-8/6-9 Computer Use（Docker 或 VL-32B 高费用）、6-10~6-14 机器人（真机硬件/GPU）。6-1/6-3 与 6-2 机制重叠，做一个即可。

## 四、问题与解决

1. **venv 没有 pip**：本次环境由 uv 创建，`python -m pip` 报错。改用 `uv pip install --python <解释器路径> anthropic PyPDF2 beautifulsoup4 html2text pytest pytest-asyncio`
2. **模型循环不终止**：表面是模型「笨」，根因在环境（9009 空输出）。修 Harness 比改 prompt 有效——这正是本章「约束优先于指导、错误变成模型输入」的一次亲身体验
3. **模型名被误判**：starter 的模型名校验假设直连官方厂商，接 SiliconFlow 这类 OpenAI 兼容端点时需要按 base_url 区分
4. **6-2 找不到输入文件**：`tasks.py` 的 `DEFAULT_INPUT` 按相对路径指向 `../../book/chapter4.md`（教程仓库布局），本地产物区缺该文件 → 把 `chapter4.md` 复制到 `d:\ai-agent-book\book\`
5. **6-2 一个测试的 POSIX 假设**：`test_cancel_terminates...` 末尾用 `os.kill(pid, 0)` 应抛 `ProcessLookupError` 来证明进程已死，但 Windows 上该探测不抛此异常。取消逻辑本身已由 returncode 与 canonical 门禁证明正确，判定为测试断言的平台差异

## 五、收获与思考

1. **「测试通过」作为完成标准的含金量**：离线 162 个测试让我在不花一分钱的情况下确认了 16 个工具可用；真实任务里 Bash 的输出就是 Agent 的「测试结果」，看到 `Hello, World!` 才允许收尾。
2. **元能力的含义具体了**：dynamic-form 里 Agent 不被限定为「填预定义表单」，而是直接产出一段带 JS 运行时的新表达形态——UI 是代码生成的副产品，这就是「运行时创造工具」。
3. **故障恢复是工程差距最大的一环**：正文的重复指纹/看门狗/熔断不是抽象理论，我在第一次运行里亲眼看到了没有这些机制时的死亡螺旋。生产级 Coding Agent 应检测「同一工具 + 同一参数指纹」的连续重复并提前熔断。
4. **小模型的启示**：Qwen3-8B 能完成 Write+Bash 闭环，但不太遵循「用绝对路径」这类自然语言约束——再次印证**能写进环境/工具层面的约束，就不要留给模型自觉**。
5. **异步的本质是「不被单个动作卡住」**：3.03x 并行加速只是表象，更关键的是 Agent 在后台任务跑着的时候仍能即时回答问题、能被安全打断并完整恢复——这是从「一问一答」走向「长期在线、多事并发」的通用 Agent 的必经一步。
6. **检查点是异步 Agent 的安全带**：轨迹 + 任务进度落盘后，进程可以被杀、会话可以换，状态不丢。这与第五章的 Git 回退一脉相承，都是「可靠回退」原则。
