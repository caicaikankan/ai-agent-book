

# 第3章：优化推理延迟

当模型运行正常后，下一个挑战就是速度。目标是在降低**延迟**的同时提升**吞吐量**，即系统每秒处理的请求数。这两个指标通常存在权衡关系。

最重要的优化技巧是**键值缓存**（KV cache）。在推理过程中，若不使用缓存，模型需要在每一步重新计算所有先前标记的注意力。通过缓存历史标记的键和值向量，模型只需处理最新标记，这使得长提示的延迟大幅降低。

```python
def decode_step(new_token, kv_cache):
    q, k, v = project(new_token)         # 仅处理新标记
    kv_cache.append(k, v)                # 重用历史键和值
    return attention(q, kv_cache.keys, kv_cache.values)
```

第二个优化技巧是**批量处理**（batching）：将多个提示合并处理以保持硬件利用率。更大的批量可以提升吞吐量，但可能增加单个请求的延迟，因此服务系统会谨慎调整批量大小。

核心结论是：推理性能需要平衡。我们每避免一次重新计算，每成功合并一个提示，就能同时推动系统向更低延迟和更高吞吐量迈进。
