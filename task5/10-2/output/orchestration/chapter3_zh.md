

# 第3章：优化推理时延

一旦模型运行起来，接下来的挑战就是速度。目标是降低**时延**，同时提高**吞吐量**（系统每秒处理的请求数）。这两者通常相互权衡。

最重要的技巧是**键值缓存**（KV cache）。在推理过程中，模型原本需要在每一步重新计算对所有先前词元的注意力。通过缓存过往词元的键和值向量，模型只需处理最新的词元，这大幅降低了长提示词的时延。

```python
def decode_step(new_token, kv_cache):
    q, k, v = project(new_token)         # 仅处理新词元
    kv_cache.append(k, v)                # 重用过往的键和值
    return attention(q, kv_cache.keys, kv_cache.values)
```

第二个技巧是**批量处理** [待审]：将多个提示词合并处理以保持硬件持续工作。更大的批次可以提高吞吐量，但可能增加单个请求的时延，因此服务系统会谨慎调整批次大小。

核心原则是推理性能需要在两者之间取得平衡。每一次避免重新计算的词元，以及每一次有效批量处理的提示词，都会同时推动系统向更低的时延和更高的吞吐量迈进。
