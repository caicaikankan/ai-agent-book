## 一、学习目标回顾

1. 掌握多 Agent 设计的两个维度：**上下文是否共享**、**协作拓扑形态**
2. 理解本章核心判据：多 Agent 只有引入单 Agent 无法内生的**新信息通道**时才真正有效
3. 跑通管理者模式（Manager + 专职 Agent + 共享文件系统），实测上下文膨胀如何被控制
4. 双臂对比「共享上下文的角色移交」与「上下文隔离的技能调用」，理解各自适用边界
5. 跑通并行 Agent + 消息总线 + 级联终止，实测并行加速与资源清理
6. 认识多 Agent 的失败模式与沟通开销，避免「为拆而拆」

---

## 二、核心知识脉络

本章回答：**什么时候该把一个 Agent 拆成多个，怎么拆，代价是什么。**

- **上下文维度**：共享上下文信息不丢但会膨胀、产生「角色惯性」；不共享则靠三种通信机制——工具调用参数（同步消息）、共享文件系统（=共享内存）、消息总线（异步消息）
- **拓扑形态**：对等协作（2~3 个 Agent 迭代）、管理者模式（Manager 只做调度）、去中心化（handoff 网络）
- **核心判据**：自我审查、同上下文辩论不引入新信息，等计算量下与单 Agent 持平甚至有害；测试结果、渲染截图、外部工具验证带来新信息，才显著提升
- **Loop 工程**：由验证器（而非模型自己）决定能否停；提议者-审核者；级联终止；预算感知
- **失败模式**：并发冲突、错误级联、同质趋同、互相扯皮、循环失控、理解债

## 三、实验记录

### A. 10-2 书籍翻译：管理者模式 vs 单 Agent（本章主线）

任务：把一本 4 章英文技术书翻成中文，且专业术语全书必须统一。两种做法：

- **单 Agent**：一个 Agent 从头翻到尾，全部原文、译文堆在同一条对话里
- **管理者模式**：Manager 只排日程；术语专家先定术语表落盘；翻译专家各翻一章（各自独立上下文，只共享术语表文件）；审校专家最后出报告，Manager 据此决定哪章返工

离线自检（零费用）：

```text
14 passed                          # pytest 全套
python demo.py --dry-run           # 打印协作图与 token 预算，不调 API
```

**真实双臂对比结果（Qwen3-8B）：**

| 指标 | 管理者模式 | 单 Agent |
| --- | --- | --- |
| Manager / 主上下文峰值 | **883 tok** | **2101 tok**（2.4 倍） |
| 指定术语遵从率 | **100%** | **27%** |
| 术语内部一致率 | 89%（8/9） | 78%（7/9） |
| 全流程总 token | 14672 | 8293 |

逐角色 token 账（管理者模式）：Glossary 峰值 1246 / Translation 4 次各约 440~480 / Proofreading 1352 / Manager 559。

**两个关键读法：**

1. **总 token 团队反而更高**（14672 > 8293）——多 Agent 不省总花费，买的是 **Manager 上下文与书长解耦**（只随章节数加几行记录）和**术语一致性**。书越长，883 vs 2101 的差距越致命。
2. **术语遵从率为何 100% vs 27%**：术语专家把 `token=词元、prompt=提示词、latency=时延、embedding=嵌入向量` 写进共享术语表强制下发；单 Agent 没人定规矩，于是 token 整本书翻成「标记」、latency 一章「延迟」一章「时延」。

审校报告抓出 3 处问题（术语表缺「键值缓存」「批处理」、第 3 章部分句子流畅性），Manager 据此把第 3、4 章发回修订——返工决策由报告（验证器）驱动，而非模型自觉。

### B. 10-1 多角色转换：Transfer vs Skill

复合任务需检索 → 算 CAGR → 写投资人摘要，三种专业能力接力。对比两种切换方式：

- **Transfer（移交 / 共享上下文）**：同一段对话、同一段历史，只换系统指令，模型带着上一角色的全部材料继续
- **Skill（技能 / 独立上下文）**：主助理把任务打包，派一个全新的、脑子空白的专业助手，只拿任务所需信息，只回交结果

离线自检：**14 passed**。

Demo 的自主移交链跑通：`triage → research → coding → writing`，3 次移交，每次附理由；research 调 Tavily、coding 真实执行 Python、writing 用字数工具约束后交稿。

**配对对比（3 个任务 × 3 轮，各 9 次）：**

| 路径 | 完整交差 | 平均调用次数 | 平均耗时 |
| --- | --- | --- | --- |
| Transfer 移交 | **0 / 9** | 4.3 次 | 117 s |
| Skill 技能 | **3 / 9** | 8.3 次 | 229 s |

**为什么调用少反而是坏事**：Transfer 是「没干完就停」——身份换几轮后模型搞不清当下职责，草草收尾；Skill 调用多、耗时多，是每个新专家把自己那部分真正做完整才交结果。分任务看，Skill 的 3 次成功全部来自短写作任务；CAGR 与斐波那契任务两条路径都未达标（8B 小模型长链任务能力有限）。

结论与教程一致：**模型不够强时，共享上下文的角色移交难以收尾，上下文隔离更可靠**。

### C. 10-4 并行网页搜索：并发 + 消息总线 + 级联终止

任务：在斯坦福多个学院教师名录里找 人。串行是一个浏览器挨个翻；并行是同时开 3 个**独立 browser context**，任一找到即在消息总线上广播一次 `terminate`，其他 Agent 在安全点停止——级联终止。

离线自检：**13 passed**。

**真实浏览器两种场景实测：**

| 场景 | 并行耗时 | 串行耗时 | 加速比 | 级联广播 | context 关闭 |
| --- | --- | --- | --- | --- | --- |
| not_found（医/法/教育学院） | 23.5 s | 30.3 s | **1.285** | 0（确实没找到） | 6/6 |
| found（profiles 页命中） | 39.7 s | 49.9 s | **1.257** | 1 次 | 6/6 |

**为什么不是 3 倍加速**：启动浏览器等固定开销并行省不掉，整体时间由最慢的网站决定（水桶效应）；网站越多、单站越慢，并行优势才越大。

**意外验证——同名 人与证据约束**：profiles 页上的 「Andrew Ng」 实为另一位财务岗同名人。Agent 只把网页真实渲染出的文字抄回（职位原样保留），没有脑补成「AI 教授」——证据约束（看到什么说什么）生效，无幻觉。

**Ch.10 其余实验按门槛跳过**：10-3 自动注册（WebRTC/TTS/ASR 硬件链）、10-6 语音狼人杀（语音回环，Windows 需大改）；10-5 斯坦福 AI 小镇为 📖 档（官方跑了 17,280 步，规模过大），按复现指南阅读理解。

## 四、问题与解决

1. **ch10 环境不含 pytest**：`uv sync --extra ch10` 后 `No module named pytest`。追加 `--extra dev` 即可
2. **对比运行首轮挂起**：某网络调用卡死十几分钟、进程无 CPU。用项目自带的 checkpoint 机制 `--resume` 续跑，并加 `--request-timeout 60 --max-steps 12` 防止再次挂死，已完成的 6 组不重跑
3. **Tavily 返回错误销量**：demo 中检索把 2021 年销量返回成 11.9 万辆（实际约 352 万），导致 CAGR 错误。协作机制本身正常（移交、执行、交稿都对），属检索数据质量问题，如实记录而非换结果
4. **Tee 管道无输出**：`Tee-Object` 在长任务下因缓冲未生成对比日志文本；完整轨迹与指标都在 JSON 报告里，证据链不受影响

## 五、收获与思考

1. **「新信息」判据是一把好用的尺子**：10-2 的审校报告、10-4 的真实页面渲染都是单 Agent 关起门变不出来的东西；而同上下文自辩没有新信息，拆了也白拆。以后判断要不要多 Agent，先问「第二个 Agent 能带来什么新证据」。
2. **多 Agent 买的是可控性，不是省 token**：10-2 团队总花费更高，但 Manager 脑子轻 2.4 倍且术语 100% 统一。规模越大，「上下文与正文解耦」的价值越超过多花的那点 token。
3. **共享文件系统是最朴素的共享内存**：术语表落盘后，各翻译 Agent 独立开工却口径一致，Manager 只持有路径不持有正文——用文件切断上下文膨胀，比让一个 Agent 硬扛优雅得多。
4. **上下文隔离对弱模型更友好**：Skill 3/9、Transfer 0/9 让我直观看到「角色惯性 + 身份错乱」的代价。强模型或许能压住共享上下文，工程上默认隔离更稳。
5. **级联终止的关键是「不浪费剩余劳动 + 干净收尾」**：找到即停、只广播一次、12 个 context 全部关闭。并行省下的时间虽只有 1.26 倍，但资源不泄漏、消息不重复，是比加速比更重要的工程底线。
6. **证据约束是防幻觉的护栏**：同名 人事件里模型没把财务岗脑补成 AI 教授，「只复述页面可见文字」这一条约束，比事后审稿更根本。
