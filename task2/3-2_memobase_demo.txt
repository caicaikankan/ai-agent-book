def sum_list_recursive(lst):

## 🚨 Common Causes of Stack Overflow in Recursive Functions

Based on my experience and your functional programming preferences, here are the primary causes:

---

### 1. **Missing or Incorrect Base Case** ⭐ Most Common
```python
# ❌ No base case
def countdown(n):
    return countdown(n - 1)

# ❌ Base case never reached
def countdown(n):
    if n == 0:
        return 0
    return countdown(n + 1)  # Moving away from 0!
```

### 2. **Insufficient Recursion Depth**
Python's default limit is ~1000 calls. Large inputs will overflow:
```python
import sys
print(sys.getrecursionlimit())  # Default: 1000
```

### 3. **No Tail Call Optimization** ⚠️
Python doesn't optimize tail recursion, unlike functional languages:
```python
# Even this will overflow eventually
def factorial(n, acc=1):
    if n <= 1:
        return acc
    return factorial(n - 1, n * acc)  # Tail call - still no optimization in Python
```

### 4. **Exponential Recursion Without Memoization**
```python
# ❌ Recomputes same values repeatedly
def fibonacci(n):
    if n <= 1:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)  # O(2^n) calls!

# ✅ With caching
from functools import lru_cache
@lru_cache(maxsize=None)
def fibonacci(n):
    if n <= 1:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)
```

### 5. **Infinite Recursion Loops**
```python
# ❌ Circular reference
def process(data):
    return process(data)  # Calls itself with same input

# ❌ State not changing
def transform(lst):
    return transform(lst)  # List never modified
```

### 6. **Deep Data Structures**
- Trees/lists with thousands of nodes
- Nested function calls without proper depth control
- Large input sizes not suited for recursion
