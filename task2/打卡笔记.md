## 二、核心知识脉络

本章回答：**跨会话的信息怎么留、外部的知识怎么进。**

- **用户记忆**：对话原文不是记忆。记忆是会话结束后经「提取 + 压缩 + 审查」得到的结构化档案，跨会话存活，新会话再检索注入；记忆写入要考虑更新（避免矛盾）、脱敏（隐私）与评测。
- **知识库（RAG）**：文档分块 → 稀疏（BM25）+ 稠密（Embedding）双路检索 → RRF 融合 → 重排注入。复杂问题升级为 Agentic RAG（模型自主拆解、多轮检索）；对多跳/概述类问题可用知识图谱与 RAPTOR 层次树。
- 二者在章末合流：记忆档案做大后同样用 RAG 技术检索，形成「概览常驻 + 细节按需检索」的**双层记忆**；本质上 Memory 就是面向用户历史的 RAG。

## 三、实验记录

### A. 用户记忆

**实验 3-1：用户记忆 notes vs json_cards（扩展对比，产物在 task1/）**
同一段两轮会话分别用两种格式落档：notes 为 5 条平铺句子（1922B，姓名重复 5 次、不能原地更新）；json_cards 为两层结构化树（1445B，独立 identity、叶子级覆盖更新、每字段带溯源时间戳）。核心认知：模型本身没有记忆，所谓长期记忆是开新会话时把硬盘档案重新注入上下文。

**实验 3-2（1）：Memobase 手写记忆 Agent**
跑通含 episodic/semantic/procedural/working 四类记忆、pickle 持久化的手写 Agent，demo 三组场景（记忆保持、经验学习、上下文管理）全部成功，跨轮正确记住「最爱 Python、函数式风格」。

**实验 3-2（2）：mem0 真实框架**
用真实 `mem0ai` 2.x 框架，LLM=Qwen2.5-14B-Instruct、embedder=bge-m3、本地 Qdrant。输入两句中文（住北京/后端/Python → 搬到上海/仍做后端），框架自动抽取出两条结构化事实；查询「现在住哪个城市」「做什么工作、用什么语言」均正确召回最新事实（搬上海，score 0.68）。

**实验 3-3：记忆写入隐私脱敏**
离线 regex 规则对 5 类真实样本脱敏：API Key、密钥、邮箱、手机号、身份证、银行卡、SSN 均命中替换（如工具调用日志命中 4 处、客服对话命中 4 处）。理解：记忆在落库前必须先过脱敏，防止 PII/密钥长期沉淀。

**实验 3-5：记忆检索质量评测**
在 10 篇内置语料上用 recall@5 / precision@5 / MRR 评测 BM25，宏平均 recall 0.80、MRR 0.80；「cat」查「kitten/feline」相关文档漏召回（同义词短板），量化了纯关键词检索的边界。

### B. 知识库与索引

**实验 3-6：检索流水线三路线对比（产物在 task1/，零 API 费）**
同一批中文查询：BM25 Recall@3=0.833（语义改写失败）、Dense=1.0（近重复排错）、**Hybrid-RRF=1.0 满分**——稀疏与稠密错误模式正交，RRF 只按排名融合即可兼得两者之长。

**实验 3-4：稠密向量索引 ANN 对比（ANNOY vs HNSW）**
官方依赖 annoy/hnswlib 在 Windows 无预编译 wheel，改用 **numpy 手写 RPForest**（50 棵随机投影树，复刻 ANNOY 等距超平面二分思想）+ **usearch**（工业级 HNSW，有 Win wheel），向量走 SiliconFlow bge-m3，语料/评测口径与官方 benchmark 完全一致：

| 指标 | RPForest（ANNOY 思想） | HNSW（usearch） |
| --- | --- | --- |
| recall@10 | 0.99 | **1.0** |
| 构建时间 | 69.7 ms | **5.08 ms** |
| 单次查询 | 0.366 ms | **0.034 ms** |
| 序列化体积 | 15.1 MB | **1.02 MB** |
| 增量 20% 数据 | 114 ms，需全量重建 | **3.86 ms，原地插入** |

结论与书一致：HNSW 更快、更小、增量友好；随机投影森林实现简单但更新代价高。

**实验 3-7：结构化索引 vs 扁平检索（RAPTOR / 知识图谱）**
x86 SIMD 指令集知识库（10 实体、13 关系、1 棵层次树）上对比：① 多跳推理——扁平检索只捞回词面相近的孤立片段，图检索沿「ADDPS→属于→SSE→需要启用→CR4.OSFXSR」2 跳给出答案；② 跨节点对比——图检索沿同一关系边取回两侧事实直接综合出「SSE 用 128 位 XMM、AVX 用 256 位 YMM」；③ 概述类问题——RAPTOR 返回上层摘要节点，避免碎片细节答不了宏观问题。

### C. Agentic / 进阶检索

**实验 3-8：Agentic vs 非 Agentic RAG（产物在 task1/）**
21372 个法条分块离线评测：复杂题证据召回 **8% → 100%**，平均检索 1.0 → 1.5 次。在线同一道多跳题（醉酒过失致人重伤+盗窃前科）：非 agentic 单次检索捞回不适用法条后放弃；agentic 用 ReAct 拆成 4 个子查询、4 轮 16 次检索，找到《刑法》§18、§235 分层作答。检索召回是答案质量的上限。

**实验 3-9：记忆场景 Agentic RAG**
2 个历史会话（保险 + 保养，切 6 个记忆块），问题「我给车预约了什么保养」：朴素单次检索 recall **0.5**（漏掉本田已确认预约 FS-447291）；Agentic 自主改写 5 次查询（Honda/Tesla/Model…），recall **1.0**，两辆车的预约全部覆盖。

**实验 3-10：上下文感知检索（Contextual Retrieval）**
本地 13 块中文法律语料、15 个查询，对比直接索引原始块与为每块预生成上下文摘要后再索引：Recall@1 **0.667 → 0.733**（典型提升来自「国家的根本任务」等脱离语境就缺乏检索信号的查询），Recall@3 均为 1.0。

**实验 3-11：用户记忆的上下文化**
12 个记忆块、8 个查询：Plain 的 Recall@1=0.625/MRR=0.792 → Contextual **0.750 / 0.875**。如「西雅图酒店确认了吗」从第 3 名升到第 1 名——孤立句「好的，就订这个吧」被锚定回预订情境后才可被检索。

**实验 3-12：从案例中抽取隐性知识（结构化知识抽取）**
用官方 66 案合成集完整跑通四段流水线：① 自下而上因子发现（82 个原始因子归并为 14 个核心因子 schema）；② JSON 结构化抽取（6 并发，66 次调用 45s 完成）；③ 各罪名内 KMeans 聚类（轮廓系数选 k）得 **10 个案件原型**；④ 对话式建议 Agent 先抽取已知事实、追问缺失要素，最终匹配到入户盗窃**原型 #5（15 例，刑期中位 49 月，区间 27~67 月）**，建议基于原型统计生成并附免责声明。说明：官方验收 campaign 用 420 个真实 CAIL2018 案例（费用高），本实验用自带合成集验证机制，数据规模差别已如实记录。

## 四、踩坑与环境备注

- `uv sync --extra ch3` 在 Windows + Python 3.12 失败（annoy/hnswlib 均需 MSVC 编译）：annoy 用 numpy 手写 RPForest 教学复刻，hnswlib 用有预编译 wheel 的 usearch 替代
- 本机无 GPU/不装 torch，稠密向量统一走 SiliconFlow **bge-m3** API（1024 维），仍是真实稠密向量
- 书默认大模型 Qwen/Qwen3.5-35B-A3B 当天平台排队严重（长时间挂起），切换同能力稳定模型 **Qwen/Qwen2.5-14B-Instruct** 后全程顺畅
- SiliconFlow 仅允许一个 system 消息且必须在开头：memobase 把记忆上下文并入唯一 system 后才成功
- mem0 三个配置坑：向量维度默认 1536（需显式 `embedding_model_dims: 1024`）；历史库默认在用户目录被沙箱拦截（`history_db_path` 重定向到工作区）；新版 `search/get_all` 不再接受顶层 `user_id`，必须用 `filters={"user_id": ...}`

## 五、结论：Memory、RAG 与 Context 的关系

**Context 是唯一进入模型的容器，Memory 和 RAG 是两条供给通道。** Memory 沿时间轴纵向沉淀用户历史，RAG 沿知识轴横向引入外部文档；二者都不直接喂模型，必须先检索、筛选再注入 Context。本章实验完整验证了这条链路：记忆怎么存（3-1/3-2）、怎么脱敏与评测（3-3/3-5）、知识怎么索引（3-4/3-6/3-7）、检索怎么做准（3-8/3-9/3-10/3-11），以及如何从非结构化经验中提取可复用的结构化知识（3-12）。
