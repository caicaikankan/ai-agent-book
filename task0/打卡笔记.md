# Task 0 打卡｜AI Agent 基础与环境搭建

> 教程：《深入理解 AI Agent：设计原理与工程实践》第 1 章
> 实验：实验 1-1 上下文的关键作用（消融实验）
> 模型：DeepSeek（deepseek-v4-flash）

## 一、环境搭建

- 安装第 1 章依赖：`uv sync --locked --extra ch1`（58 个包）
- 在项目根目录创建 `.env`，填入 `DEEPSEEK_API_KEY`
- 运行方式（工作目录必须是项目根目录）：

```powershell
# 单次任务
uv run python chapter1/context/main.py --mode single `
  --task "把1000美元换算成欧元、英镑、日元并求平均值" --provider deepseek

# 消融实验（两个离线财务任务，5 种上下文模式 × 2 任务 = 10 组）
uv run python chapter1/context/main.py --mode ablation --provider deepseek --cases 2
```

踩坑记录：
1. `.env` 在编辑器里粘贴后必须 **Ctrl+S 保存**，否则程序读到的还是空文件
2. 消融实验默认任务要从 GitHub 下载 PDF，国内网络打不开，改用 `--cases 2` 跑内置离线任务
3. 不指定 `--provider` 会默认走豆包并报缺 key，必须显式指定

## 二、单次任务：直观理解 ReAct 循环

任务：把 1000 美元换算成欧元、英镑、日元并求平均值。

Agent 用 3 轮迭代（Thought → Action → Observation）完成：

1. 第 1 轮：并行调用 3 次 `convert_currency`（€920 / £790 / ¥149,500，模拟汇率）
2. 第 2 轮：调用 `calculate` 求算术平均 50,403.33
3. 第 3 轮：给出最终答案，并主动指出"不同币种直接取算术平均没有货币意义"

这正好对应书中的核心公式：**Agent = LLM + 上下文 + 工具**，以及 ReAct 循环——下一步做什么（调哪个工具）是模型根据当前上下文自主决定的，而不是代码写死的流程。

## 三、消融实验：砍掉上下文会怎样

同一个任务，分别去掉上下文中的不同组件，对比结果：

| 上下文模式 | 迭代轮数 | 工具调用 | 是否给出答案 | 数字是否可信 |
| --- | --- | --- | --- | --- |
| full（完整基线） | 3 | 4 | ✅ | ✅ 全部来自工具返回（年均 $9,602,895.73） |
| no_history（去掉历史消息） | 10（触顶） | 30 / 32 | ❌ 无答案 | 反复调用同样的工具，陷入死循环 |
| no_reasoning（去掉思考过程） | 3 | 4 | ✅ | ✅ 与基线完全一致 |
| no_tool_calls（去掉工具定义） | 1 | 0 | ⚠️ 假完成 | ❌ 凭空编造，复杂任务 6 个数字全错（如 $9,621,000） |
| no_tool_results（去掉工具结果） | 6~7 | 10~11 | ⚠️ 假完成 | ❌ 看不到返回值，改用"参考汇率"瞎猜（$9,600,000） |

## 四、我的结论

1. **历史消息决定任务的连贯性**。没有记忆，Agent 每轮都"失忆"，只能不断重复同一个动作，永远走不到下一步——上下文就是 Agent 的"记忆"。
2. **工具定义决定能力边界，工具结果决定事实依据**。最危险的不是报错，而是 `no_tool_calls` / `no_tool_results` 这种"假完成"：模型语气自信、格式完整，但数字全是编的（ungrounded）。没有观测，模型就会用自己的参数记忆冒充事实。这也解释了为什么后续章节要讲 RAG 和 Agent 评估。
3. **思考过程的作用与任务难度有关**。这两个结构化简单任务上，去掉显式推理毫无影响；可以预期在复杂编码、多步决策任务上差距才会拉开。
4. 整体体会：Agent 并不存在于模型权重里，而是**由上下文在运行时构建**的——同一个模型，给不同的工具、历史和指令，就是不同的 Agent。
