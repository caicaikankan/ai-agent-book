## 一、学习目标回顾

1. 理解工具在 Agent 公式（Agent = LLM + 上下文 + 工具）中的位置：工具是 Agent 的「手脚」，把模型意图变成对外部世界的感知与改变
2. 掌握工具发现的三种策略：全量注入、检索式预筛选、主动工具发现，并能从 token 成本与任务成功率两个维度量化取舍
3. 跑通 MCP 标准下的感知工具、执行工具、协作工具实验
4. 理解多模态感知三范式：原生多模态、先抽文本再推理、多模态分析工具
5. 理解执行工具的多层安全机制（验证 → 审批 → 截断 → fail-safe）

---

## 二、核心知识脉络

本章回答：**Agent 怎么发现工具、怎么安全地用工具、怎么把非文本信息变成可用输入。**

- **工具分类与 ACI**：感知工具（获取信息）、执行工具（改变世界）、协作工具（驱动其他 Agent/人类）。工具设计应对齐 Agent 的目标而非底层 API，即 ACI（Agent-Computer Interface）。
- **工具发现三策略**：
  - 全量注入：把所有工具 schema 放进上下文，工具数线性涨 token，且干扰选择
  - 检索式预筛选：按初始查询一次性匹配 top-k；多步任务进入第二领域时系统性漏召回
  - 主动发现：执行中按需声明「能力缺口」、动态注入新工具；新 schema 追加到上下文末尾，避免击穿 KV Cache
- **MCP（Model Context Protocol）**：开放的工具接入标准。**实际踩出版本分裂**——4-2 用 MCP v2（mcp 2.2.0，协议 2026-07-28），4-4/4-5 用 MCP v1 + fastmcp，两套 API 不兼容。
- **多模态三范式**：① 原生多模态直接读图/文档；② 先用 caption/OCR/转写抽成文本再推理；③ 把多模态分析做成工具供模型按需调用。
- **执行安全**：输入 linter → 权限审批（提议者-审核者）→ 长输出截断落盘 → 危险命令 fail-safe 拒绝；沙盒隔离与幂等性。

## 三、实验记录

### A. 工具发现：离线可量化对比

**实验 4-1：active-tool-discovery（8 任务 × 3 策略，纯离线 mock）**

工具池 126 个工具、8 个任务（含 finance+news、forex+weather、crypto+news 等多域组合任务和两个诱导任务）：

| 策略 | 成功任务 | 平均注入 token | 失败模式 |
| --- | --- | --- | --- |
| 全量注入 | **8/8** | 11,630 | 无，但每次为 2 个工具背 126 个 schema |
| 检索预筛选 | **4/8** | ~1,030 | 多步任务第二领域工具漏召回（forex+weather 中汇率工具被召回但模型判为「不可用」；诱导任务也漏） |
| 主动发现 | **8/8** | ~974 | 无 |

主动发现以约 1/12 的 token 拿到与全量注入相同的成功率，**省 11.9 倍**。关键机制是执行中两次调用 `discover_tools`：例如 forex+weather 任务先按「查汇率」缺口取回 get_forex_rate/convert_currency，调用后再按「查天气」缺口取回 get_current_weather，每步只暴露 4 个候选。

**实验：active-tool-selection（离线 benchmark + 规模扩展）**

10 个任务的 gold 工具检索，retrieval top-5 全部命中（recall 1.0）：

| 工具总数 | 全量注入 schema token | retrieval top-5 token | retrieval recall |
| --- | --- | --- | --- |
| 35 | 3,857 | 516.6 | 1.0 |
| 50 | 5,342 | 521.7 | 1.0 |
| 100 | 10,292 | 521.7 | 1.0 |
| 200 | 20,258 | 521.7 | 1.0 |
| 400 | **40,258** | **521.7** | **1.0** |

全量注入随工具数线性增长，检索式恒定约 522 token，400 工具时省下 **98.7%** 的 schema 开销且不掉召回。

### C. 多模态

**实验 4-3：multimodal-agent（SiliconFlow Qwen3-VL-8B-Instruct）**

- 离线 `create_sample.py` 生成样本：柱状图（Q1~Q4 营收 120/150/95/180，**精确数字只标注在柱子上**）+ PDF 报告（正文只给定性描述）
- 同一问题「Which quarter had the highest revenue, and what was the exact value?」跑三范式：
  1. **原生多模态**：直接读图，正确答出 Q4 = **$180M**，并列出四个季度全部数值
  2. **先抽文本**：caption 详细描述了坐标轴、颜色和柱顶标注（恰好保留了精确数值），再推理仍正确答 Q4 = $180M
  3. **抽文本 + 工具**：模型 function-calling 时**幻觉出一个不存在的文件名**（Acme_Corp_Quarterly_Revenue_2024.png）导致首轮失败；在问题中显式给出绝对路径后，analyze_image 工具调用成功，答案正确
- PDF 场景：原代码原生 PDF 路径只支持 Gemini；改用 **pypdf 抽正文文本 + 提取内嵌图表**一起送入 Qwen-VL 的混合方式跑通，同样得到 Q4 = $180M
- pytest：**19 passed**

样本的教学设计让范式取舍可测量：若 caption 模型只描述「一张显示季度营收的柱状图」而丢掉柱顶数字，先抽文本范式就必然答错——这正是精确数字只放在图里的原因。

## 四、踩坑与环境备注

1. **MCP 版本分裂**：4-2 必须用 MCP v2（`mcp>=2,<3`），为它单独建 `.venv-mcp2` 虚拟环境；4-4/4-5 用 v1 + fastmcp。两套环境互不污染。
2. **Windows 跨平台修复（4-4）**：
   - `multilang_executor.py` 硬编码 `python3` 和 `executable='/bin/bash'`，本机子进程报 WinError 3。改为 `sys.executable` 并按 `os.name` 分支选择 shell
   - demo 步骤 5 原用 Unix `wc -w`，改为 PowerShell 统计行数，并让命令读 `$env:WORKSPACE_DIR` 环境变量以避开多层引号嵌套问题
3. **pytest async 用例**：4-5 有 5 个 async 测试报「async def functions are not natively supported」，加 `-o asyncio_mode=auto` 后正常
4. **平台差异用例（如实记录，未强行通过）**：Windows 非管理员不能建符号链接（WinError 1314）；`select.select` 不支持管道 fd（WinError 10038）；openpyxl 文件句柄未释放导致 unlink 失败（WinError 32）
5. **网络环境**：Open-Meteo、汇率 API、PubChem（NCBI）可达；arxiv 返回 406、wikipedia/Yahoo 返回 403、youtube 超时；扫描常见本地代理端口均无开放。境外站点不可达属环境网络限制，非代码问题，相关实验以离线 mock/测试覆盖
6. 模型 function-calling 会幻觉文件路径，工具化多模态方案需要在提示中提供真实路径或在工具侧做路径校验

## 五、结论

本章实验串成一条完整链路：**工具太多时靠发现策略控成本**（4-1/selection：主动发现与检索预筛选把 4 万 token 压到 500 量级且不掉召回），**工具落地时靠 MCP 标准化接入**（4-2/4-4/4-5：感知、执行、协作三类），**非文本输入靠多模态范式处理**（4-3），**改变世界的操作靠多层安全机制兜底**（4-4：linter、审批、截断、fail-safe）。最大的体感是：工具能力 ≠ 工具数量，把正确的工具 schema 在正确的时机放进上下文，才是工具工程的核心。
